# Архитектура версии Godot

## Нативные элементы вместо HTML/Canvas

| HTML-версия | Godot 4.7.1 |
| --- | --- |
| \`src/map.js\`: массив ландшафта | \`Village/Ground\`, \`Roads\`, \`Water\`, \`Bridge\` — \`TileMapLayer\` |
| \`src/renderer.js\`: рисование дорожек через canvas | Изображения \`TileSetAtlasSource\` в \`resources/tilesets/village.tres\` |
| \`src/assets.js\`: нарезка исходного атласа | Импортированные индивидуальные PNG в \`art/environment/\` |
| \`src/world.js\`: массив объектов | Отдельные \`Node2D/Sprite2D/StaticBody2D\` внутри \`village.tscn\` |
| \`src/assets.js\`: выбор кадров героя | Ресурсы \`SpriteFrames\` + \`AnimatedSprite2D\` |
| HTML-меню и CSS | \`CanvasLayer/Control/PanelContainer/Button\` в \`scenes/base/hud.tscn\` |
| \`localStorage\` | Автозагрузка \`GameState\` и файл \`user://\` |
| поиск пути в JS | \`AStarGrid2D\`, использующий нарисованную карту и сохранённые коллизии |

## Сцены и их назначение

- \`scenes/main.tscn\`: композиция уровня и интерфейса.
- \`scenes/world/village.tscn\`: всё окружение, размещённое в редакторе.
- \`scenes/base/player.tscn\`: \`CharacterBody2D\`, спрайт и камера.
- \`scenes/base/npc_*.tscn\`: NPC со спрайтами и коллизиями.
- \`scenes/base/enemy_*.tscn\`: настройки противников в инспекторе, спрайты, таймеры.
- \`scenes/base/herb.tscn\`: собираемая трава.
- \`scenes/base/hud.tscn\`: все окна и кнопки UI.

## Физика и взаимодействие

Вода — TileSet с физическими полигонами. У зданий и непроходимых декораций есть \`StaticBody2D\` с \`CollisionShape2D\`. Герой и враги — \`CharacterBody2D\`. Это реальная физика Godot, не HTML-проверка координат.

Мышь отдаёт команду пойти по координатам; AStarGrid2D маршрутизирует вокруг объектов. WASD двигает непосредственно CharacterBody2D. Е взаимодействует с NPC и травами. Пробел наносит удар ближайшему врагу. Сцены героев и NPC редактируются без генерации кода.

## Принципы роста

Базовая механика сознательно небольшая. Нельзя добавлять новый HTML-подобный «бог-скрипт», отрисовывающий всю игру. Для новых RPG-предметов и квестов позднее разумно добавить самостоятельные Resource-каталоги. Для MMO потребуется серверная авторитетность и отделение данных игроков от клиентского \`GameState\`.

### Происхождение ассетов

Изображения перенесены из \`CrossDoomDev/MyGameHTML\`, ссылка на точный коммит сохранена в \`data/world_layout.json\`. Артефакты на левом краю \`cottage\`/\`forge\` очищены при импорте. Исходные оригиналы находятся в \`assets/original/\` и не используются для отрисовки во время игры.

## Персонаж — только 2D

Игровой герой использует `CharacterBody2D`, `AnimatedSprite2D` и один ресурс `res://resources/animations/hero.tres`. Режимов 3D и переключения спрайта нет. Анимации редактируются в интерфейсе Godot. Старые сохранения открываются без миграции: устаревший параметр `hero_model` игнорируется.
